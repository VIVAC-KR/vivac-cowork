## 0. 확정 사항

### D1. 데이터 범위 — 공공 운영 시설만, 민간은 post-MVP *(2026-08-09 확정)*

MVP에 포함하는 "국가주도 야영장"은 **공공이 운영하는 시설**로 한정한다.
산림청 자연휴양림 · 국립공원 야영장 · 지자체 국민여가캠핑장 등.
**민간 오토캠핑장·글램핑장은 MVP 제외, MVP 이후 확장 항목으로 명시적으로 남긴다.**

- 근거: "국가시설 = 합법 자명" 논리를 유지해야 합법성 축 절반이 공짜로 확보됨.
  민간을 넣는 순간 개별 확인이 필요해져 논리가 깨지고, 캠핏·고캠핑과 정면 경쟁이 됨.
- 감수하는 것: 커버리지가 얇음(현재 191건). "통합 탐색"이라는 이름 대비 빈약해 보일 수 있음.
- 이월된 숙제: 민간 확장 시 위 합법성 논리를 어떻게 다시 세울지는 그때 재설계.

### D2. 유형 체계 — 노지는 단일 버킷, 차박·비박은 속성 *(2026-08-09 확정)*

MVP의 category는 **공공 야영시설 / 노지** 2종. 차박·비박은 별도 category가 아니라
**접근 방식 속성(도보 진입 / 차량 진입)**으로 내린다.

- 근거: 노지 실데이터가 현재 0건인 상태에서 3분할하면 빈 필터 칩만 늘어남.
  속성 → category 승격은 나중에 가능하지만 그 반대는 어려움.
- 감수하는 것: "차박 스팟 찾기"가 1급 진입점이 되지 못함.
- ~~이월된 숙제: 기존 category 코드 `CAR_CAMPING`·`BIVOUAC` 처리~~
  → **전제 오류. 해당 코드는 존재하지 않는다.** BE 화이트리스트(`spot_field_option`,
  field=category)에 등록된 코드는 `BACKPACKING`·`RECREATIONAL_FOREST` **2개뿐**이다
  (`packages/shared/src/constants/spotCategory.ts`가 이를 미러링).
  프로덕션 질의에서 `CAR_CAMPING`·`BIVOUAC`이 0건이었던 것은 "데이터 없음"이 아니라
  **"코드 없음"**이었다. → 실제 어휘 정리는 **D11**.

### D3. 합법성 표기 — 관할·연락처·최종확인일 3필드 필수 *(2026-08-09 확정)*

순연 대상은 **네거티브 폴리곤 레이어로 한정**한다. 노지 스팟은 등재 시
**관할 기관 · 연락처 · 최종 확인일** 3필드를 필수로 채운다.

- 약속의 크기: "합법 여부의 정답을 준다"가 **아니라** "문의 비용 자체를 줄인다".
  → 가치 제안 문구를 이 크기에 맞춰 잠글 것 (스파이크 문서 §가치 역설의 축소 시나리오).
- 근거: 개발비 ≈ 0(필드 3개 입력). 표기 없이 핀만 찍으면 "여기서 자도 된다"로 읽혀
  불법 야영 유도 구조가 되고, 공유 자제 ↔ 데이터 해자 딜레마에 명분이 사라짐.
- 감수하는 것: 운영 입력 부담이 스팟당 고정으로 붙어 노지 적재 속도가 느려짐.
- 이월된 숙제: "최종 확인일"이 얼마나 오래되면 경고를 띄울지(신선도 임계) 미정.

### D4. "통합 탐색"의 정의 — 두 과업의 함의 *(2026-08-09 확정, 사용자 문구)*

**해결하려는 부재:**
- 기존 캠핑장 예약 서비스는 **자사와 계약을 맺은 캠핑장만** 노출한다.
- 국가 주도 야영장은 **관할 지자체·국가기관별로 예약 페이지·소개 사이트가 분산**되어 있다.
- → 여러 장소를 한 번에 비교하고 정보를 열람할 수 있는 플랫폼이 없다.

**과업 1 — 국가 운영 야영장의 통합 탐색**
국가에서 운영되는 **모든 형태의 야영장** + **둘레길 코스(추후 추가)**를
한 곳에서 탐색할 수 있는 경험을 제공한다.

**과업 2 — 노지 백패킹 스팟의 양지화**
캠핑 동호회·커뮤니티에서 암암리에 공유되던 노지 백패킹 야영 스팟 정보를 양지화하고,
동시에 합법적 야영 가능 여부를 **신뢰 가능한 수준의 필터링**을 통해 제공하여
믿을 수 있는 백패킹 박지 정보를 만든다.

> "통합 탐색"은 위 두 과업을 함의하는 표현이다. (계약 기반 부분 노출 → 전수 / 분산 → 집약)

**파생 메모**
- **둘레길 코스: MVP 단계에서 구현하지 않는다.** 추후 구현 예정이라는 점만 기록하고 넘어간다.
  *(2026-08-10 확정)* — 지금 모델을 선형 데이터까지 수용하도록 일반화하지 않는다.
- "국가 운영 **모든 형태**"는 D1(공공 한정)과 정합. 자연휴양림에 편중된 현 191건은
  국립공원 야영장·국민여가캠핑장까지 넓혀야 과업 1이 성립.

→ 과업 2의 "신뢰 가능한 수준의 필터링"이 D3보다 큰 약속인 문제는 **D5로 해소**.

### D5. 약속의 크기 — 지향점과 MVP 과제를 분리 *(2026-08-09 확정)*

D4 과업 2의 **"신뢰 가능한 수준의 필터링"은 서비스가 지향하는 궁극적 지향점**이다.
**현재 실현 단계의 MVP 달성 과제는 D3의 최소 수준**(관할·연락처·최종확인일 3필드로
문의 비용을 줄인다)으로 설정한다.

- 따라서 D3과 D4는 충돌이 아니라 **같은 축의 서로 다른 지점**이다.
  MVP = 정보 집약 → 이후 = 필터링/판정으로 상향.
- 대외 문구 규칙: **MVP 시점의 가치 제안은 D3 크기로 표기한다.**
  "합법 야영지만 모았다"류의 표현은 MVP에서 쓰지 않는다.
- 이월된 숙제: 지향점(필터링/판정)으로 올라가는 조건 = 스파이크 실행 결과.
  스파이크는 여전히 미실행이며 상향 시점의 게이트로 남는다.

### D6. 진입 경험 — 목록 우선, 지도는 전환 모드 *(2026-08-09 확정)*

기본 진입은 **목록(조건·필터 중심)**, 지도는 **토글로 전환하는 모드**로 둔다.
현재 구현된 2모드(list|map) 구조를 그대로 유지한다.

- 근거: 좌표 보유 54건·노지 0건 상태에서 지도 우선 진입은 전국에 핀 54개 =
  빈 서비스로 보임. 목록은 속성 데이터가 채워지는 만큼 즉시 가치가 오름. 추가 개발 없음.
- 감수하는 것: "지도 기반 탐색"이라는 원 가설을 정면으로 검증하지는 못함.
- 이월된 숙제: 데이터가 어느 밀도에 도달하면 지도 우선으로 뒤집을지 — 전환 기준 미정.

### D7. 가설 — 과업별 2개로 분리 *(2026-08-09 확정)*

**H1 — 국가 운영 야영장의 통합 탐색**
> 관할 기관별로 흩어져 있던 공공 야영시설을 한 곳에서 같은 기준으로 열람·비교할 수
> 있으면, 백패커가 갈 만한 곳을 추려 나가는 **탐색 경험이 개선된다.**

**H2 — 노지 백패킹 스팟의 양지화**
> 커뮤니티에 암암리에 공유되던 노지 스팟을 관할·연락처·최종확인일과 함께 공개하면,
> 백패커가 박지 후보를 찾고 확인하는 **탐색 경험이 개선된다.**

- "주말 목적지를 정한다"는 단정을 쓰지 않고 **탐색 경험 개선**으로 문구를 완화했다.
- H1·H2는 **각각 따로 검증되고 따로 실패한다.** 하나로 묶지 않는다.
- 마일스톤 표: **§2**.

### D8. MVP 판정 기준과 단계 *(2026-08-09 확정)*

**MVP 우선순위**
1. **탐색 플랫폼 구현**
2. **최대한 많은 데이터를 수집·정제하여 서비스에 반영**

**판정 기준: MVP는 데이터 마일스톤만으로 판정한다.**
행동 지표 2종(상세 2건 이상 열람, 아웃바운드 클릭)은 MVP 게이트에서 제외한다.

**단, 사용자 행동 계측 시스템 도입은 MVP 달성 직후 반드시 반영한다.**
"안 한다"가 아니라 **"MVP 다음 순번의 필수 항목"**이다. (현재 저장소에 계측 전무)

**노지(H2) 착수 시점**
- 최소 물량 수치는 두지 않는다.
- 백패커들이 많이 찾는 **유명 명소·백패킹 성지 위주**로 먼저 작업한다.
- 단, 이는 **기본 장소 탐색 구현이 완료된 이후 추가로 기획**할 내용이다.

**⚠ 구조적 귀결 — H1과 H2는 같은 파도가 아니다**
위 착수 시점 규정에 따라 실행 순서는 다음과 같이 갈라진다.

| 단계 | 내용 | 가설 |
|---|---|---|
| 1 | 탐색 플랫폼 구현 + 공공 데이터 수집·정제 → **MVP 판정** | **H1** |
| 2 | 계측 도입 (필수) / 노지 성지 위주 적재 기획·착수 | H2 준비 |
| 3 | 노지 노출 (D3 3필드 필수) | **H2** |

- 따라서 **MVP 시점에는 D4 과업 2(양지화)가 아직 사용자에게 보이지 않는다.**
  MVP 대외 문구를 D5 크기로 잠그는 것에 더해, **노지를 MVP 홍보에 쓰지 않는 것**까지
  포함해야 약속과 실물이 어긋나지 않는다.
- ~~이월된 숙제: "기본 장소 탐색 구현 완료"의 정의~~ → **D10으로 확정**

### D9. 자연휴양림 편중 — 블로킹 아님, 해소로 닫음 *(2026-08-10 확정)*

현재 191건 중 169건(88%)이 자연휴양림인 것은 **적재 순서 artifact**로 판단한다.
산림청 데이터가 정돈되어 있어 먼저 들어왔을 뿐이며, 데이터 확보가 진행되면 해소된다.

- 근거(추정, 미검증): 공공 야영시설 모집단은 자연휴양림 약 170 + 국립공원 야영장 30~40
  + 국민여가캠핑장·지자체 야영장 수백 규모. 최종 400~600건대라면 휴양림 비중은 **30~40%로 희석**.
  → 고캠핑 API로 확인 가능. 확인 전까지 가정으로 둔다.
- 초기 제기(Q4)의 오류: 88%를 수렴점처럼 다뤘음. 수집 중간 상태였다.
- "MVP가 백패커의 핵심 수요(노지)를 다루지 않는다"는 지적은 **D8에서 이미 의도적으로
  선택한 사항**이라 새 문제가 아니다(중복).
- **이월**: MVP 출시 시 대외 문구에서 타겟을 어떻게 말할지(백패커 유지 / 넓힘 / 미언급)
  — 코드·스키마와 무관하므로 **출시 시점에 실제 분포를 보고 결정**한다.
- 수집 우선순위(국립공원을 휴양림보다 앞에 둘지)도 블로킹 아님. 운영 순서라 변경 비용 낮음.

**별건 메모 — 다중 소스 스키마 정규화** → **D13으로 확정** (공개 스키마 고정, ETL이 흡수)

### D10. "기본 장소 탐색 구현 완료"의 정의 — 지도 SDK 통합까지 *(2026-08-10 확정)*

D8이 말하는 "기본 장소 탐색 구현 완료"는 **지도 SDK가 통합되어 지도 모드가 실제 좌표로
동작하는 시점**이다. 목록 모드만으로는 완료가 아니다.

- 근거: D6이 지도를 "전환 모드"로 남겼으므로 지도가 없으면 D6이 성립하지 않는다.
  PRODUCT.md MVP 우선순위 #2(지도 표시)도 충족되지 않는다.
  노지(H2)는 주소가 없어 좌표가 유일 식별자이므로 지도가 선행되어야 한다.
- 현황: 목록·필터·무한스크롤·바텀시트·상태화면은 구현 완료(설계 문서 Stage 1 ✅ 2026-08-06).
  지도 SDK 미통합, `/map` 404.
- ~~남은 작업: 지도 SDK 선정~~ → **D14로 확정(네이버)**. 남은 작업은 통합 → 실좌표 연동.
- 이월된 숙제: 상세 페이지는 이 정의에 포함하지 않았다. 다만 H1 행동 지표
  (상세 2건 이상 열람·아웃바운드 클릭)는 상세 동선이 있어야 측정 가능하므로,
  계측 도입(D8 2단계) 시점에 상세 완성도를 함께 봐야 한다.

### D11. category 어휘 — 시설 유형 그대로 4종 *(2026-08-10 확정)*

`category`는 **시설 유형을 그대로** 값으로 갖는다.

| 값 | 라벨 | 현황 |
|---|---|---|
| `RECREATIONAL_FOREST` | 자연휴양림 | 등록됨 |
| `NATIONAL_PARK_CAMPGROUND` | 국립공원 야영장 | **신규 — D12에서 확정** |
| `PUBLIC_CAMPGROUND` | 공공 캠핑장 | **신규 — D12에서 확정** |
| `BACKPACKING` | 백패킹(노지) | 등록됨, 실데이터 0건 |

- D2의 "공공 / 노지 2종"은 폐기가 아니라 **상위 그룹**(필터 UI 1단계)으로 물러난다.
  합법성 축(공공=자명 / 노지=불확실)은 이 상위 그룹이 계속 표현한다.
- 근거: H1 첫 마일스톤("공공 3유형 모두 1건 이상")을 `category` 분포로 **그대로 측정**할 수 있다.
  사용자도 휴양림과 국립공원 야영장을 구분해 찾는다(예약 방식·시설 수준이 다름).
- 비용: BE 화이트리스트에 코드 2개 추가 + 적재 시 유형 분류 작업.
- ~~이월된 숙제: 신규 코드 2개의 정확한 코드명은 BE와 합의 필요~~ → **D12로 확정**

### D12. 신규 category 코드명 확정 *(2026-08-10 확정 — BE 협의 없이 결정)*

| 코드 | 라벨(한국어) | 포함 범위 |
|---|---|---|
| `NATIONAL_PARK_CAMPGROUND` | 국립공원 야영장 | 국립공원공단 운영 야영장 |
| `PUBLIC_CAMPGROUND` | 공공 캠핑장 | 국민여가캠핑장 + 지자체 운영 야영장 |

- **세 번째 코드를 `국민여가캠핑장`이 아니라 `PUBLIC_CAMPGROUND`(공공 캠핑장)로 넓힌 이유:**
  D9의 모집단 추정상 지자체 운영 야영장이 국민여가캠핑장보다 많다. 좁게 잡으면 곧
  네 번째 코드가 필요해진다. 또 "국민여가캠핑장"은 공식 명칭이지만 사용자에게 익숙하지
  않아 필터 라벨로 부적합하다.
- 이에 따라 H1 첫 마일스톤의 "3유형"은 `RECREATIONAL_FOREST` /
  `NATIONAL_PARK_CAMPGROUND` / `PUBLIC_CAMPGROUND` 세 코드를 뜻한다.
- **알려진 명명 불일치**: `BACKPACKING`은 시설 유형이 아니라 활동명이라 나머지 셋과
  결이 다르다. 이미 등록·사용 중이므로 **바꾸지 않는다**(마이그레이션 비용 > 이득).
- 반영 지점: BE `spot_field_option`(field=category) 등록 +
  `packages/shared/src/constants/spotCategory.ts` 정적 미러 갱신.

### D13. 소스 확장은 공개 스키마를 바꾸지 않는다 *(2026-08-10 확정 — BE 협의 없이 결정)*

국립공원공단·고캠핑·지자체 등 **소스가 늘어도 공개 API 계약(`SpotListItem`/`SpotDetail`)은
바꾸지 않는다.** 소스별 필드 차이는 ETL 단계에서 흡수한다.

- D9에서 "미리 보면 싸지는" 항목으로 남겼던 다중 소스 스키마 정규화 건의 결론.
  소스별 필드를 대조해 공개 스키마를 맞추는 대신, **공개 스키마를 고정하고 ETL이 맞춘다.**
- 근거: 공개 스키마가 소스를 따라 흔들리면 FE가 소스마다 분기해야 한다.
  현재 계약은 이미 4개 소스를 커버할 만큼 일반적이다(이름·좌표·주소·연락처·링크·속성).
- 소스에만 있고 계약에 없는 필드는 **버리거나** 기존 속성 필드에 매핑한다.
  새 필드를 추가해야 한다면 그때 별건으로 판단한다.
- 감수하는 것: 소스 고유 정보 일부 손실.

| 네이버 | 열세 | **우세** — 한 벤더가 웹·앱 관통 |

3. 무료 600만 건 **초과 단가가 공식 요금표에 미표기**(요금계산기로만 산출).
4. **⚠ 미검증 리스크 — TERRAIN.** 네이버 TERRAIN은 NORMAL/SATELLITE/HYBRID와

   **육안 검증 없이 확정한 항목이다.** 통합 초기에 실제 산악 지역에서 확인할 것.

**⚠ 알려진 경계 — 해외 확장 시 재검토 필수**
카카오는 공식적으로 "데이터 범위는 대한민국으로 한정", 네이버도 해외 커버리지가 제한적이다.
**일본 등 해외 캠핑 명소 표시는 네이버 SDK로 구현 불가능하다.**
해외가 로드맵에 오르는 시점에 SDK를 다시 정해야 하며, 그때의 유력 후보는

### H1 — 국가 운영 야영장의 통합 탐색

> 관할 기관별로 흩어져 있던 공공 야영시설을 한 곳에서 같은 기준으로 열람·비교할 수
> 있으면, 백패커가 갈 만한 곳을 추려 나가는 탐색 경험이 개선된다.

| 층 | 마일스톤 (MVP) | 측정 |
|---|---|---|
| 데이터 | 공공 야영시설 **3유형(자연휴양림·국립공원 야영장·국민여가캠핑장)이 모두 1건 이상** 노출 — 현재는 사실상 자연휴양림 단일 | `category` 분포 |
| 데이터 | 노출 스팟의 **좌표 100%**, **주소·연락처 90%↑**, **예약/안내 링크 80%↑** | 전수 집계 (현재 좌표 28.3%, 주소 27%, 링크 17%) |
| 데이터 | 같은 기준으로 비교 가능해야 하므로 **비교 핵심 속성 4종(화기·편의시설·예약방식·접근성) 채움률 70%↑** | 전수 집계 |
| 행동 | 1세션당 **상세 2건 이상 열람 비율** — "비교가 실제로 일어났다"의 대리 지표 | ⚠ 계측 미도입 |
| 행동 | 상세 → **외부 예약·안내 링크 아웃바운드 클릭률** | ⚠ 계측 미도입 |

### H2 — 노지 백패킹 스팟의 양지화

> 커뮤니티에 암암리에 공유되던 노지 스팟을 관할·연락처·최종확인일과 함께 공개하면,
> 백패커가 박지 후보를 찾고 확인하는 탐색 경험이 개선된다.
> (약속 크기는 D5 — 합법 판정이 아니라 **문의 비용 절감**)

**⚠ H2는 MVP 게이트가 아니다.** D8에 따라 기본 장소 탐색 구현 완료 이후 단계(3단계)의
달성 기준이다. 아래 표는 "노지를 노출하려면 무엇이 충족되어야 하는가"이다.

| 층 | 달성 기준 (3단계) | 측정 |
|---|---|---|
| 데이터 | 노지 스팟 확보 — **수치 목표 없음.** 유명 명소·백패킹 성지 위주 (D8) | `category` 집계 |
| 데이터 | 노지 스팟의 **D3 3필드(관할·연락처·최종확인일) 채움률 100%** — 미충족 시 미노출 | 전수 집계 |
| 데이터 | 노지 좌표 **100%** (주소가 없어 좌표가 유일 식별자) | 전수 집계 |
| 데이터 | **최종 확인일 1년 이내 비율 90%↑** (신선도) | 전수 집계 |
| 행동 | 노지 상세 열람 중 **관할 연락처 노출·클릭 비율** — "문의 비용을 줄였다"의 대리 지표 | ⚠ 계측 미도입 |

### 표 해석 규칙 *(2026-08-09 확정)*

- **⚠ 계측 미도입** 행동 지표 2종은 **MVP 판정 기준이 아니다.** → D8

## 3. 방향에 동의하는 근거 (추가 논거)

국가주도 야영장은 합법성이 자명하다(산림청·지자체·국립공원공단 운영). 따라서
`국가시설 + 노지` 조합은 **이미 합법성 축을 절반 내장**한다.

| 데이터 | 합법성 |
|---|---|
| 국가주도 야영장 | 확실 — 별도 검증 불필요 |
| 노지 야영스팟 | 불확실 — 검증 대상 |

이 구분은 기존 `trust_tier`(1/2/3) 구조 및 PRODUCT.md의 "모두 보여주되 신뢰도를
밝힌다" 원칙과 그대로 정합. → 순연이 곧 차별점 포기는 아님 (아래 조건부).

## 4. 함께 정해야 할 조건 3가지

### (1) "통합"의 축을 명시해야 함 → **D4로 확정됨**
PRODUCT.md가 스스로 "단순 통합은 차별점이 아니다"라고 기재. 따라서 **무엇과 무엇의
통합인지**가 차별이어야 함.
- 고캠핑·캠핏 = 예약형 시설만 / 오지캠핑지도·야영 = 노지만
- **양쪽을 한 화면에서 비교 가능한 서비스는 없음**
- ~~제안 축: "예약해서 가는 곳과 그냥 가는 곳을, 같은 지도에서 비교한다"~~
  → 채택되지 않음. **D4의 두 과업 정의로 대체됨** (계약 기반 부분 노출 → 전수 / 분산 → 집약)

### (2) 병목은 사라지지 않고 이동함 — 노지 데이터 현재 **0건**
2026-08-07 프로덕션(api.vivac.app) 전수 확인:

| category | 건수 |
|---|---|
| `RECREATIONAL_FOREST` | 있음 (전체 191건의 대부분) |
| `BACKPACKING` | **0** |
| `CAMPING_GROUND` / `CAR_CAMPING` / `BIVOUAC` | **0** |

- 제안한 2종 중 **차별을 만드는 쪽(노지)이 아직 존재하지 않음**
- 순연의 실제 효과 = 리스크 제거가 아니라 **합법성 실현성 → 노지 데이터 조달**로 이동
- 함정: 노지를 운영 검수로 넣으면 검수자가 "이 노지가 합법인가"를 판단해야 함.
  합법성 판정이 제품에서 사라진 게 아니라 **운영 프로세스로 이동**. 개발비 0, 운영비 유지.
- → **순연의 조건: 노지 검수 기준(무엇을 확인하면 등재하는가)은 미룰 수 없음**

### (3) 합법성을 0으로 만들지 말고 가장 싼 형태로 유지 → **D3으로 확정됨**
스파이크 설계 문서 §가치 역설의 축소 시나리오 그대로:
**"정답을 준다"가 아니라 "관할·연락처·최종확인일을 모아 문의 비용을 줄인다."**
- 폴리곤·판정 로직·지도 레이어 불필요. 필드 3개(관할 기관/연락처/최종 확인일) 입력 작업. 개발비 ≈ 0
- 표기 없이 노지 핀만 찍으면 사용자는 **"여기서 자도 된다"로 읽음** → 불법 야영 유도 구조
- PRODUCT.md 미해결 이슈(공유 자제 ↔ 데이터 해자)가 전면화 — 명분 없는 위치 공개가 됨
- 권고: 순연 대상을 **"네거티브 폴리곤 레이어"로 한정**, "관할·최종확인일 표기"는 노지 필수 필드로 유지
