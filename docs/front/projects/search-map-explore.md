# 검색 지도 탐색 (search-map-explore)

> 작성일: 2026-08-04
> 배경: 현재 `/search`는 리스트 단일 모드입니다. 지도 기반 탐색을 추가해 목록/지도 2개 모드로 확장합니다. BE 계약(좌표·`bbox`)이 아직 없어 목(mock) 기반으로 UI를 선행 구현합니다.
> 선행 문서: [`search.md`](search.md) — 이 문서는 `search.md` §4.1·§4.2가 예고한 승격 문서입니다.
> 참고(구현 근거 아님): [`archive/spots-explore-plan.md`](../archive/spots-explore-plan.md) — 2026-07-15 폐기된 `/spots` 리스트·지도 토글 설계. 컴포넌트 분해 방식만 참고했습니다.

## 1. 한 줄 요약

검색 결과를 목록/지도 2개 모드로 탐색할 수 있게 하고, 지도와 리스트를 양방향 동기화합니다. 지도 모드는 데스크탑에서 리스트+지도 분할, 모바일에서 지도+스냅 바텀시트로 표현됩니다. BE 좌표 데이터가 준비되기 전까지 **MSW 목 기반으로 UI를 완성**하는 것이 이번 범위입니다.

## 2. 역할 정의

지도는 **탐색 도구**(새로운 장소를 발견), 리스트는 **비교 도구**(후보를 비교·결정)입니다. 두 표면의 정보 밀도와 인터랙션 설계는 이 구분을 따릅니다.

## 3. 결정 사항 요약

| 항목 | 결정 | 근거 |

## 4. BE 계약 의존

확정된 요청 내역과 각 항목의 근거는 [`backlog/search-map-schema-request.md`](../backlog/search-map-schema-request.md)에 있습니다. 요약하면 좌표 필드 추가, `bbox` 파라미터, 좌표 없는 스팟 제외, `total`, 지도용 경량 응답, 커서-bbox 검증 6건입니다.

**FE 일정의 유일한 외부 의존은 좌표 데이터 적재 시점**입니다. 계약 형태만 확정되면 실제 구현 전이라도 목으로 병렬 진행합니다.

## 5. 목(mock) 기반 선행 구현

### 5.1 MSW 목 사양

`packages/api/src/mocks/handlers.ts`가 현재 빈 배열(`handlers: RequestHandler[] = []`)이라 이 파일에 등록합니다.

**제공 필드** — 확정된 계약 범위까지만 채웁니다. 미확정 필드(합법·식수·취사·조용함 등)는 **의도적으로 비웁니다.** 임의로 넣으면 계약 확정 후 전부 다시 손대야 합니다.

| 필드 | 목 값 | 프로덕션 실측(2026-08-04) |
|---|---|---|
| `uid` / `title` | 프로덕션 실제 값 수집 | 정상 |
| `latitude` / `longitude` | 합성 좌표 | 전부 null |
| `trust_tier` | 1·2·3 혼합 | 전부 2 |
| `thumbnail_url` | 70% null | 전부 null |
| `region_short` | 40%만 채움 | 대부분 null |
| `category` | 20%만 채움, 코드 형식 | 대부분 null |

**재현할 서버 동작** — 데이터보다 이쪽이 중요합니다. 목이 동작까지 재현해야 UI가 실제 상황을 다루게 됩니다.

- `bbox` 사각형 내 필터링 (실제 좌표 비교 연산)
- 커서 페이지네이션 — `next_cursor` 발급·소비
- `bbox` 불일치 시 `400 CURSOR_SCOPE_MISMATCH` → FE 에러 복구 흐름 검증
- `total` 상한 캡 + `total_capped`
- 좌표 없는 스팟 제외
- 없는 uid → 404
- **인위적 지연·실패 주입** (300ms 지연, 5% 확률 500) — 로딩 스켈레톤·에러 상태를 실제로 확인

**데이터셋 설계 방침 — 낙관이 아니라 비관으로**

- 총 8,000건 — 예상 최종 규모와 동일하게 맞춰 성능을 실측합니다
- 지역 편중 — 강원·경북·충북에 몰리게 배치(자연휴양림 실제 분포). 균등 분포로 만들면 클러스터링 임계값을 낙관적으로 잡게 됩니다
- 극단 케이스 포함 — 20자 넘는 장소명, 좌표가 100m 내로 겹치는 쌍, 도서 지역 고립 핀
- 실제 장소명 + 합성 좌표 조합. 프로덕션 공개 API에서 `uid`/`title`/`trust_tier`를 수집하고 좌표만 합성하면 이름 길이·표기 편차가 현실적이라 레이아웃 깨짐을 미리 잡을 수 있습니다

### 5.2 지도 SDK 후보

| 후보 | 장점 | 단점 |
|---|---|---|
| **카카오맵 JS v3** (권장) | `react-kakao-maps-sdk` 커뮤니티 래퍼가 성숙해 App Router 통합 비용이 가장 낮음, MarkerClusterer 내장, **지형도 레이어 확인됨(아래)** | 도메인 사전 등록 필요 |
| 네이버 지도 JS v3 | 국내 지형·등산로 표현이 가장 낫다는 평, 클러스터링 공식 예제 | npm이 아닌 스크립트 로드, 타입 비공식, React 래퍼 생태계 약함 |
| MapLibre GL JS + 국내 벡터 타일 | 오픈소스, 스타일을 완전히 커스터마이즈할 수 있어 `DESIGN.md` 토큰을 지도까지 적용 가능 | 국내 타일 소스 직접 구성 필요, 초기 셋업 비용 |

기획 초안이 지정한 **Mapbox는 채택하지 않습니다.** 한국 정밀 지도 반출 규제로 국내 상세도에 제약이 있고 유료입니다.

**검증 경과 (2026-08-06)** — 가리왕산(강원 정선, 1,561.8m)을 카카오맵에서 열어 확인했습니다.

- 기본 지도에서도 정상 표고, 중봉·하봉 등 봉우리, 임도갈림길·어은동 같은 **등산로 분기점이 지명으로 표시**되고 능선 경로가 선으로 이어집니다.
- **지형도 레이어**(지도설정 → 지형도)를 켜면 등고선 + 음영기복으로 능선·계곡 구분이 선명해집니다. 백패킹 후보지의 접근 난이도를 지도만 보고 가늠할 수 있는 수준입니다.

→ 초안이 카카오의 단점으로 적었던 "지형 표현이 약함"은 **지형도 레이어를 켜면 해소**됩니다. 다만 이 레이어를 JS SDK v3에서 켜는 방법(오버레이 맵타입 지정)은 SDK 연동 시점에 함께 확인해야 합니다.

> ⚠️ **미완 — 네이버 비교**: 네이버지도는 자동화 브라우저의 안전 정책으로 접근이 차단되어 같은 지점 비교를 하지 못했습니다. 카카오 단독 평가만으로도 요구 수준은 충족하지만, 초안이 전제한 head-to-head 비교는 남아 있습니다. **네이버가 결정적으로 나은지 확인이 필요하면 수동으로 같은 좌표를 열어 대조**해주세요 — 그 결과가 없으면 위 근거로 카카오를 확정합니다.

## 6. 미확정 — 이번 범위에서 제외

계약이 없어 착수할 수 없는 항목입니다. 각각 별도 요청으로 진행합니다.

| 항목 | 막힌 이유 |
|---|---|
| 신규 필터 10종 | 다중 선택·디바운스·활성 개수·초기화 *메커니즘*은 기존 `useSpotFilters`에 있어 재사용 가능하지만, **어떤 칩이 몇 개 어떤 그룹으로 존재하는지**가 미정이라 필터 바를 확정할 수 없습니다 |
| 정렬 | 옵션 목록 미확정 |
| 자동완성 | 엔드포인트 계약 미확정 |
| 미니카드 핵심 배지 | 합법·식수·취사·조용함 4개를 "어디서도 숨기지 않는다"는 것이 제품 원칙인데, 이 4개가 미확정이라 배지 슬롯의 크기·개수·배치를 확정할 수 없습니다. **미니카드는 레이아웃만 잡고 배지 영역은 비워둡니다** |
| 카테고리 라벨 | 옵션 공개 API가 없어 `packages/shared/src/constants/spotCategory.ts` 하드코딩 유지 |

> 🔴 **선행 확인 필요** — `searchFilterOptions.ts`가 한글 라벨(`"자연휴양림"`)을 그대로 `category=` 로 전송하는데 API는 코드(`RECREATIONAL_FOREST`)를 기대합니다. **기존 카테고리 필터가 이미 동작하지 않는 상태**입니다. 필터 바 확장 전에 이 불일치부터 해소해야 합니다.

**가장 큰 병목은 필터 계약입니다.** P0~P3이 다 끝나도 상단 필터 바가 비어 있으면 화면이 완성되지 않습니다. 지도 블로커 요청 전달과 동시에 필터 데이터 모델 논의를 시작해야 하며, 특히 "조용함"의 판정 기준과 합법 여부 enum은 제품 판단이 필요해 논의가 길어질 가능성이 높습니다. 합법 여부 enum은 [`design/decisions/spot-detail-design-decisions.md`](../../../../vivac-frontend/design/decisions/spot-detail-design-decisions.md) §11.4.1이 3단계(초록/빨강/앰버)를 전제로 색상 편차까지 승인해둔 상태라 그 문서와 값을 맞춰야 합니다.

| 현재 위치 버튼 | 브라우저 Geolocation API — 데이터 무관 |
| 성능 최적화 | 지도 이동 100ms / 카드 선택 50ms / 초기 렌더 2.5s를 8,000핀으로 실측 |
| 접근성 | 키보드 탐색, 핀 `aria-label`, 44px 터치 영역, 포커스 링, 색상 외 선택 표시 |

**여기까지가 "최소한의 퍼블리싱" 범위**이며, 기획 초안의 P0·P1·P2·P3이 모두 포함됩니다. 좌표만 있으면 되고 그 좌표가 진짜일 필요가 없기 때문입니다.

### 7.3 3단계 — 실 데이터 연동

BE 좌표 적재 완료 시점에 MSW 핸들러를 제거합니다. 계약대로 내려오면 코드 수정 없이 동작합니다.

**연동 시 재조정이 예상되는 지점**

- 합성 좌표와 실제 좌표의 **밀도 차이** → 클러스터링 임계값 재조정
- 지오코딩 정확도가 낮으면 핀 위치 오차 → 정확도 등급을 받아 "대략적 위치" 표기로 방어 (스키마 요청 §질문 2)
- `thumbnail_url`·`region_short`·`category`의 실제 null 비율
