# 수익화 & 비즈니스 기능 로드맵

> 제품 정의·MVP 범위는 [PRODUCT.md](../../../PRODUCT.md)가 기준입니다. 이 문서는 **MVP 이후 기능 후보** 목록입니다.

> 원본: `docs/business-feature-roadmap.md`(2026-07-20 작성). 성장/획득, 리텐션/인게이지먼트, 수익화/파트너십, 신뢰/데이터품질 4개 관점으로 브레인스토밍한 뒤 실제 코드(모델/엔드포인트)와 대조해 근거를 검증한 문서다.
> 상태 표기: `제안`(기본) / `🚧 진행중` / `✅ 완료` / `⏸ 보류`. 착수 시 이 저장소의 개별 설계 문서(`../<feature>.md`)로 스핀오프한다.

## 1. 성장/획득 (Growth & Acquisition)

| # | 기능 | 상태 | 요지 |
|---|---|---|---|
| 1.1 | 재사용 가능한 리퍼럴 링크 | ✅ 완료 | 일반 리퍼럴 초대를 수락 후에도 `PENDING` 유지시켜 같은 링크로 반복 가입 허용. 그룹 초대는 기존대로 1회용 유지. 어뷰징 방지는 의도적으로 스코프 밖 |
| 1.2 | 스팟 상세 공개 공유 카드(OG 메타) | 제안 | 2026-08-10 재확인 — `/spots/{uid}` 상세 페이지는 구현·배포되어 있다([PRODUCT.md](../../../PRODUCT.md) §5.5). "상세 페이지가 없다"는 구 기록은 사실이 아니다. OG 메타만 검토하면 된다 |
| 1.3 | 공개 그룹 탐색/공유 진입점 | 제안 | `PUBLIC` 그룹 상세/스팟목록은 이미 비로그인 조회 가능(백엔드 완료). 갭은 "발견 가능성" — (a) 공유 URL 노출(백엔드 변경 없음, 난이도 하) / (b) `GET /v1/groups/public` 같은 디스커버리 엔드포인트(난이도 중) |
| 1.4 | 초대 현황 대시보드("내가 보낸 초대") | 제안 | 리퍼럴 귀속 데이터는 이미 쌓이지만 조회 API가 없음 — "데이터는 있고 피드백 루프만 없는" 케이스. 1.1 이후 착수 권장 |

## 2. 리텐션/인게이지먼트 (Retention & Engagement)

| # | 기능 | 상태 | 요지 |
|---|---|---|---|
| 2.1 | 개인 찜(즐겨찾기) | 제안 | 그룹은 생성·초대가 딸린 무거운 흐름 — "일단 저장만" 하는 가벼운 니즈용 원클릭 저장. 난이도 하, 즉시 착수 가능 |
| 2.2 | 캠핑 다이어리(내 리뷰 타임라인) | 제안 | 내가 쓴 리뷰를 시간순으로 모아 보는 조회 전용 탭. 신규 쓰기 로직 없이 조회 API 하나로 완결. 난이도 하, 즉시 착수 가능 |
| 2.3 | 찜한 스팟 상태변경 알림 | 제안 | trust_tier/pipeline_status 변경 시 알림. **알림 발송 인프라(FCM/APNs, 구독 테이블) 자체가 전무** — 별도 인프라 신규 구축 필요. 난이도 상, 2.1과 4.1/4.2 선행 필요, 우선순위상 가장 늦게 착수 권장 |
| 2.4 | 그룹 활동 피드 | 제안 | "OO님이 OO 스팟을 추가했습니다" 류의 활동 로그. 활동 로그 테이블 신설 필요 여부에 따라 난이도가 갈림 |

## 3. 수익화/파트너십 (Monetization & Partnerships)

| # | 기능 | 상태 | 요지 |
|---|---|---|---|
| 3.1 | 예약 클릭 어필리에이트 | 제안 | `booking_url` 클릭을 트래킹해 제휴 채널엔 커미션, 비제휴 채널은 향후 협상 근거 데이터로 축적. 결제 인프라 없이 시작 가능한 최소 실험. 난이도 하 |
| 3.2 | 사업자 인증 파트너십(Verified Operator) | 제안 | 사업자등록번호 기반 소유권 claim → 승인 시 셀프 편집 권한 + 인증 배지. 이 셀프 관리 권한을 월 구독으로 판매하는 수익 모델. claim 승인 담당자 배정이 필요해 4.4 이후 착수 권장. 난이도 중 |
| 3.3 | 피처드 리스팅(Sponsored Placement) | 제안 | 탐색 결과 상단에 "광고" 라벨과 함께 자연 노출. 초기엔 결제 자동화 없이 수동 인보이스. 3.2(인증 파트너 확보) 이후 착수 권장. 난이도 중 |
| 3.4 | 문의 리드 판매(Pay-per-Lead) | 제안 | `booking_url`이 없는 노지/국공립 스팟 대상 — "전화 문의" 클릭을 집계해 리드 건수 기반 과금. 3.1과 이벤트 로깅 인프라 공유 가능. 난이도 하 |

## 4. 신뢰/데이터품질 (Trust & Content Quality)

| # | 기능 | 상태 | 요지 |
|---|---|---|---|
| 4.1 | 스팟 폐쇄/접근불가 신고 | 제안 | 리뷰 신고는 있지만 **스팟 자체**의 상태 이상(사유지화, 산불통제 등)을 알릴 통로가 없음 — 이 서비스에서 가장 치명적인 신뢰 훼손 시나리오. 신고 누적 시 재검증 큐 자동 편입. 4.4를 먼저 처리 권장(신고 급증 시 담당자 재분배 수단 필요) |
| 4.2 | trust_tier 신선도 기반 자동 감쇠 | ✅ 완료 | `last_verified_at` 추가 + 180일 경과 시 자동 하향/재검증 큐 편입 배치. 상세는 [04-data-pipeline-and-quality.md](./04-data-pipeline-and-quality.md). 재검증 시 갱신 경로는 후속 필요 |
| 4.3 | 리뷰의 "지금도 유효한가요?" 시그널 | 제안 | 리뷰 작성 시 boolean 필드(예: `still_accessible`) 추가 → 최근 응답 집계해 "최근 방문자 확인됨" 배지. 4.1과 연동하면 효과 커짐. 난이도 하, 즉시 착수 가능 |
| 4.4 | 검증 담당자 재할당 API | ✅ 완료 | 단건 재할당/해제, 목록 일괄 재할당, 담당자 간 물량 이전 3개 엔드포인트. 상세는 [03-admin-console-operations.md](./03-admin-console-operations.md) §3.1 |

## 5. 착수 순서 제안 (원본 로드맵 문서의 의존성 그래프 요약)

```
1.1 재사용 리퍼럴 링크 ──▶ 1.4 초대 현황 대시보드
1.3(a) 그룹 공유 진입점 (즉시 가능)

4.4 검증 담당자 재할당 ──▶ 4.1 스팟 폐쇄 신고 ──▶ 2.3 찜 상태변경 알림
4.3 리뷰 유효성 시그널 (단독 가능)
4.2 trust_tier 신선도 감쇠 (단독 가능)

2.1 개인 찜 ──▶ 2.3 찜 상태변경 알림
2.2 캠핑 다이어리 (단독, 즉시 가능)
2.4 그룹 활동 피드 (단독)

3.1 예약 클릭 어필리에이트 ─┬─(이벤트 로깅 공유)─▶ 3.4 문의 리드 판매
3.2 사업자 인증 파트너십 ──▶ 3.3 피처드 리스팅
```

**의존성 없이 즉시 착수 가능한 항목** (난이도 하): `1.1`(완료), `1.3(a)`, `2.2`, `4.2`(완료), `4.3`, `4.4`(완료)

## 6. 의사결정 원칙

이 로드맵 문서는 **우선순위를 확정하지 않는다**. 프로덕트 오너가 순서를 정해 항목을 지정하면 그때 해당 항목만 별도 설계 문서(스키마, 엔드포인트, 에러코드, 테스트 계획)로 구체화한 뒤 착수하는 방식으로 운영한다.
