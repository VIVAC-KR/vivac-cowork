# <화면 이름>

> 저장 위치는 `docs/features/<화면>.md`입니다. 이 문서는 **한 화면의 자족적 기능 명세서**입니다 — 구현자가 다른 문서를 열지 않고 이 화면을 만들 수 있어야 합니다. 정본이 정의한 값은 옮겨 적되 `정본` 열을 반드시 채웁니다([constitution.md](../meta/constitution.md) 원칙 V 한정 규정). 정본과 값이 어긋나면 정본이 맞고 이 문서가 틀린 것입니다.
> 이 문서에서 `>` 로 시작하는 안내 줄은 내용을 채운 뒤 지웁니다. 아래 머리말 블록은 남깁니다. 본문의 상대 링크는 `docs/features/` 기준이라 복사한 뒤에 열립니다.

> 대상 화면: <검색>
> 라우트: `</search>`
> 구현 저장소: `front` · `core`
> 최종 갱신: YYYY-MM-DD

> 라우트가 없는 공통 규칙 문서는 `docs/features/_shared/`에 두며 이 템플릿을 쓰지 않습니다. 구현 저장소는 약칭(front · console · core · etl · mcp · infra · ios)으로 해당하는 곳을 모두 적습니다.

## 1. 목적과 비목표

> 이 화면이 사용자의 어떤 판단을 끝내주는지 2~4문장으로 적습니다.
> "하지 않는 것"에는 인접 화면이 담당하는 **항구적 경계**만 적습니다. "이번 스프린트에 안 함"은 경계가 아니라 일정이므로 구현 저장소의 `specs/`에 둡니다.

<2~4문장. 예: 조건에 맞는 스팟 후보를 좁혀서 "어디를 더 볼지"를 결정해 줍니다. 개별 스팟을 갈지 말지는 여기서 결정하지 않습니다.>

**이 화면이 하지 않는 것**

- <한 스팟의 상세 속성 확인 — 스팟 상세 화면이 담당합니다>
- <예약 처리 — vivac은 예약을 대행하지 않고 외부 예약 링크로 넘깁니다>
- <합법 여부의 판정 — vivac은 확인 결과를 기록할 뿐 판정하지 않습니다>

**핵심 질문과의 연결** — <"어디에서 합법적이고 안전하게 야영할 수 있는가"에 이 화면이 어떻게 기여하는지 한 문장. 설명되지 않으면 지금 만들 화면이 아닙니다(원칙 III).>

## 2. 사용자와 진입

> 진입 전제 조건이 충족되지 않았을 때 무엇이 보이는지는 §6의 상태로 정의하고 여기서는 조건만 적습니다.
> 오류로 인한 이탈은 §6에, 트리거의 상세 동작은 §5에 적습니다.

| 항목 | 내용 |
|---|---|
| 사용자 유형 | <비로그인 방문자 · 로그인 사용자> |
| 진입 경로 | <홈의 검색창 제출 · 홈 큐레이션 카드 선택 · 외부 링크로 직접 진입> |
| 진입 전제 조건 | <없음 — 로그인 없이 열립니다> |
| 정상 이탈 경로 | <스팟 상세로 이동 · 홈으로 복귀> |

## 3. 표시 항목 계약

> 이 화면이 사용자에게 보여 주는 항목을 하나도 빠뜨리지 않고 적습니다. `값의 출처`는 개념 수준(어떤 정보인지)으로만 적고 필드명·응답 형태는 적지 않습니다.
> `정본` 열에는 옮겨 적은 값의 출처를 `PRODUCT.md §4.3` 형식으로 적습니다. 이 화면이 처음 정하는 값이면 "이 문서"라고 적고, 그 값은 이 문서가 정본이 됩니다.
> 한 행 안에서 일부만 옮겨 적고 나머지를 이 문서가 정했다면 그 사실을 함께 적습니다. 정본이 규정하지 않은 것을 정본 이름으로 적으면 조건 2(정본과 다른 값 금지)를 어기게 됩니다.

| 항목 ID | 라벨 | 의미 | 값의 출처(개념 수준) | 형식·단위 | 값이 없을 때 표기 | 정본 |
|---|---|---|---|---|---|---|
| D1 | <카테고리> | <스팟이 속한 시설 유형> | <스팟의 분류 값> | <자연휴양림 · 국립공원 야영장 · 국민여가캠핑장 · 지자체 야영장 · 백패킹(노지) 5종 중 하나> | <"분류 확인되지 않음" 라벨을 그대로 노출합니다> | <PRODUCT.md §4.2> |
| D2 | <최종 확인일> | <이 스팟의 정보를 마지막으로 확인한 날짜> | <검수자가 등재 시 기록한 확인일> | <YYYY-MM-DD> | <"확인되지 않음"> | <PRODUCT.md §4.4> |
| D3 | <신뢰도 표시> | <이 스팟이 어느 수준까지 검증됐는지 알리는 표시> | <스팟의 신뢰도 등급> | <3등급이면 "미검증" 뱃지, 1·2등급은 표시 없음> | <등급을 판정할 수 없으면 3등급과 동일하게 "미검증" 뱃지를 표시합니다> | <PRODUCT.md §4.3 — 단 판정 불가 시의 표기는 §4.3에 규정이 없어 이 문서가 정합니다> |

**`값이 없을 때 표기`는 필수 컬럼입니다.** 공란 · `-` · `해당 없음`을 쓸 수 없습니다. 값이 비지 않는 항목이라도 "그런 조건이 오면 무엇이 보이는지"를 문장으로 적습니다. 비워 두면 확인되지 않은 값이 확정된 사실처럼 렌더링되는 경로가 생깁니다(원칙 I·II).

항목을 감추기로 했다면 "숨김"만 적지 말고 그 자리에 무엇이 보이는지 함께 적습니다.

## 4. 안전·신뢰 표시 계약

> 아래 두 줄 중 해당하는 한 줄만 남기고 나머지 한 줄을 지웁니다. 두 줄을 다 남기거나 다 지우면 이 절은 미완성입니다.
> 노출하는 경우 아래 표가 필수이고, 노출하지 않는 경우 표를 지웁니다. `근거가 없을 때 표기`의 기본값은 `"확인되지 않음"`으로 고정이며, 다른 문구를 쓰려면 사람의 결정이 필요합니다.

- 이 화면은 허용성 속성(캠핑 가부 · 취사/화기 가부 · 출입 가부)을 노출합니다.
- 이 화면은 허용성 속성(캠핑 가부 · 취사/화기 가부 · 출입 가부)을 노출하지 않습니다 — 근거: <이 화면이 다루는 항목에 허용성 판단이 포함되지 않는 이유 한 문장>

| 속성 | 확인된 값의 표시 | 근거의 표기 방법 | 근거 기준일 표기 | 근거가 없을 때 표기 | 금지 표현 | 정본 |
|---|---|---|---|---|---|---|
| <취사·화기> | <허용 범위를 문구로 표시합니다. 예: "화로대 사용 시에만 허용">| <확인한 관할 기관명과 확인 방법을 함께 표시> | <D2(최종 확인일)를 문구 옆에 병기> | `"확인되지 않음"` | <"화기 가능", "불 피워도 됩니다"> | <PRODUCT.md §4.3> |
| <야영(캠핑) 가부> | <관할 기관이 확인해 준 내용을 그대로 문구로 표시> | <관할 기관명과 연락처를 함께 표시> | <D2를 문구 옆에 병기> | `"확인되지 않음"` | <"야영 가능", "합법", "허가됨"> | <PRODUCT.md §4.4> |
| <출입 통제·보호구역> | <통제 구간·기간을 문구로 표시> | <통제를 고지한 기관과 고지 시점을 함께 표시> | <고지 시점을 YYYY-MM-DD로 병기> | `"확인되지 않음"` | <"출입 가능", "제한 없음"> | <PRODUCT.md §4.3> |

이 표를 채울 때 항상 지키는 두 규칙입니다.

- **야영 가능 여부를 "가능/불가"의 이분법으로 표현하지 않습니다.** vivac이 기록하는 것은 판정이 아니라 확인 결과입니다.
- **허용성 상태를 색상만으로 구분하지 않습니다.** 문구 · 아이콘 · 라벨 중 하나 이상의 대체 표현을 항상 함께 둡니다.

이 두 규칙을 벗어나는 표시는 이 문서만으로 확정할 수 없고 사람의 결정이 필요합니다(원칙 I·VI).

## 5. 상호작용

> 사용자가 무엇을 하면 화면이 무엇을 하는지만 적습니다. 구현 수단(컴포넌트 · 상태관리 · API 호출 방식 · 화면 배치)은 적지 않습니다. 배치는 `docs/design/`가, 구현은 구현 저장소가 답합니다.
> `결과`는 사용자가 관찰할 수 있는 변화나 이동 화면으로 적습니다. "적절히 처리합니다"처럼 참·거짓을 판정할 수 없는 문장은 결과가 아닙니다(원칙 IV).

| 상호작용 ID | 대상 항목 ID | 트리거 | 선행 조건 | 결과(사용자가 관찰 가능한 변화 또는 이동 화면) | 실패 시 결과 |
|---|---|---|---|---|---|
| X1 | <D1> | <카테고리 필터 선택> | <없음> | <선택한 카테고리에 해당하는 스팟만 목록에 남습니다> | <직전 목록을 유지하고 M3을 표시합니다> |
| X2 | <D1~D3> | <목록 항목 선택> | <해당 항목이 목록에 노출돼 있습니다> | <그 스팟의 상세 화면으로 이동합니다> | <이동하지 않고 S6으로 전환합니다> |

## 9. 수용 기준

> `AC-01`부터 번호를 붙이고 Given / When / Then으로 씁니다. 각 항목은 §2~§8의 ID(D · X · S · M)를 참조합니다.
> 반드시 포함합니다 — (a) 주요 과업의 성공 경로 (b) 빈 결과와 오류 상태 각 1건 (c) **안전 수용 기준**: §4 표의 속성마다 최소 1건, "근거가 없는 값은 어떤 조건에서도 '허용/가능'으로 표시되지 않고 '확인되지 않음'으로 표시됩니다" 형태로 씁니다.
> 모든 항목을 GWT로 쓰지 않습니다. 핵심 경로 · 상태 전이 · 안전 규칙에만 씁니다. 나머지는 §3~§8의 표가 이미 계약입니다.

- **AC-01** — Given <조건에 맞는 스팟이 1건 이상 있고>, When <X1로 카테고리를 좁히면>, Then <해당 카테고리의 스팟만 목록에 남고 D1이 각 항목에 표시됩니다>.
- **AC-02** — Given <조건에 맞는 스팟이 0건이고>, When <검색을 제출하면>, Then <S4로 전환되고 M2가 표시됩니다>.
- **AC-03** — Given <취사·화기의 근거가 없는 스팟이 포함돼 있고>, When <그 항목이 목록에 표시되면>, Then <그 속성은 어떤 조건에서도 "허용/가능"으로 표시되지 않고 M1("확인되지 않음")으로 표시됩니다>.

## 10. 검토 체크리스트

- [ ] §4 첫 줄에 허용성 속성 노출 여부를 명시했습니다.
- [ ] §3의 모든 항목에 `값이 없을 때 표기`가 채워져 있으며 공란 · `-`가 없습니다.
- [ ] §9에 §4의 속성마다 안전 수용 기준이 있습니다.
- [ ] 옮겨 적은 값마다 `정본` 표시가 있고 정본과 값이 일치합니다(원칙 V 한정 규정).
- [ ] 구현 수단(컴포넌트 · 상태관리 · API 호출 방식 · 레이아웃)이 기재되어 있지 않습니다.
- [ ] 확정되지 않은 항목이 기재되어 있지 않습니다(미확정은 구현 저장소의 `specs/`로 보냈습니다).
- [ ] §9의 모든 수용 기준이 §2~§8의 ID를 참조합니다.
