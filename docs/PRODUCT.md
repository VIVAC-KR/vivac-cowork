## 1. 한 장 요약

### 1.1 서비스 정의

국가·공공 운영 야영시설과 노지 백패킹 스팟을 한 곳에서 탐색하는 서비스.

**AS-IS**

- 캠핑장 예약 서비스 = 자사 계약 캠핑장만 노출
- 공공 야영장 = 관할 기관별로 예약·소개 페이지 분산

**TO-BE**

1. 국가 운영 야영장의 통합 탐색
2. 노지 백패킹 스팟의 양지화 — 관할·연락처·최종확인일과 함께 공개

### 1.2 대상 사용자

**25~39세, 월 1회 이상 활동하는 백패킹 지향 액티브 캠퍼.**
백패킹을 즐기거나 캠핑에서 백패킹으로 전환·확장 중인 사용자.

**JTBD** — "새로운 백패킹 장소를 찾을 때, 여러 사이트를 돌지 않고
내 조건에 맞는 검증된 장소를 빠르게 발견하고 싶다."

### 1.3 현재 단계

**MVP 1단계** — 탐색 플랫폼 구현 + 공공 데이터 수집·정제. 구현 현황은 STATUS.md §7.

### 1.4 하지 않는 것

MVP에서 제외하는 전체 목록이다. 해제 조건은 §7.

**대상 범위**


| 항목       | 사유                             | 근거  |
| -------- | ------------------------------ | --- |
| 민간 캠핑장   | "공공 = 합법 자명" 논리 붕괴, 캠핏·고캠핑과 경쟁 | D1  |
| 노지 스팟 노출 | 3단계                            | D8  |
| 해외 지역    | 네이버 SDK 해외 미지원. 확장 시 SDK 재선정   | D14 |
| 둘레길 코스   | 선형 데이터 수용하도록 모델 일반화하지 않음       | D4  |


**기능**


| 항목                | 사유                      | 근거   |
| ----------------- | ----------------------- | ---- |
| 합법 여부 판정          | MVP 약속은 판정이 아닌 문의 비용 절감 | D5   |
| 규제 구역 네거티브 폴리곤    | MVP 이후 순연               | D3   |
| 차박·비박 별도 유형       | 노지 0건에서 3분할 시 빈 필터만 증가  | D2   |
| UGC 전반 (제보·리뷰·평점) | 추후 개발                   | §7.5 |
| 사용자 행동 계측         | MVP 판정 기준 아님. 달성 직후 도입  | D8   |
| 홍보 랜딩페이지·CBT 모집   | 판정 조건을 늘리지 않는다. 모집 수단은 별도 결정 | §7.5 |


**플랫폼**


| 항목      | 사유                      | 근거   |
| ------- | ----------------------- | ---- |
| Android | RN이라 대체로 따라오나 MVP 조건 아님 | §3.4 |
| PWA     | 폐기                      | §3.4 |
| 오프라인 캐싱 | 온디바이스 캐싱은 이후 재검토        | §3.4 |


**중장기 후보** — 폐쇄형 커뮤니티, 매너 평판, GPX·등고선 필드 도구, 장비 어시스턴트.
**확정된 계획이 아니다** → §7.5

## 2. 문제와 가설

### 2.1 해결하려는 부재


| 대상     | 현재 상태                   | 결과                 |                           |
| ------ | ----------------------- | ------------------ | ------------------------- |
| 공공 야영장 | 관할 기관별 페이지 분산           | 교차 탐색 필요           | MVP 대상                    |
| 노지 스팟  | 커뮤니티에서 비공개 공유           | 접근 불가, 합법 여부 확인 불가 | 3단계                       |
| 민간 캠핑장 | 예약 서비스가 계약 업체만 노출       | 전수 비교 불가           | **맥락 — MVP 대상 아님** (§1.4) |
| 정보 생산자 | 책임감 있는 사용자일수록 위치 공유를 자제 | 신뢰할 정보가 구조적으로 희소   | 구조적 제약 (§7.4)             |


### 2.2 가설과 달성 마일스톤

H1·H2는 각각 따로 검증되고 따로 실패한다. 묶지 않는다.
현재 수치는 STATUS.md §7.

#### H1 — 국가 운영 야영장의 통합 탐색

> 관할 기관별로 흩어져 있던 공공 야영시설을 한 곳에서 같은 기준으로 열람·비교할 수
> 있으면, 백패커가 갈 만한 곳을 추려 나가는 탐색 경험이 개선된다.

**달성 마일스톤 (MVP 판정 대상)**


| 지표               | 목표      |
| ---------------- | ------- |
| 공공 4유형 노출 (§4.2) | 각 1건 이상 |
| 좌표               | 100%    |
| 주소·연락처           | 90%↑    |
| 예약·안내 링크         | 80%↑    |
| 핵심 속성 4종 (§4.3)  | 70%↑    |


**참고 지표 (계측 미도입, 판정 제외)**

- 1세션당 상세 2건 이상 열람 비율
- 상세 → 외부 링크 아웃바운드 클릭률

#### H2 — 노지 백패킹 스팟의 양지화

> 커뮤니티에 암암리에 공유되던 노지 스팟을 관할·연락처·최종확인일과 함께 공개하면,
> 백패커가 박지 후보를 찾고 확인하는 탐색 경험이 개선된다.

**달성 기준 (3단계. MVP 판정 아님)**


| 지표           | 목표                        |
| ------------ | ------------------------- |
| 노지 스팟 확보     | 수치 목표 없음. 유명 명소·백패킹 성지 우선 |
| 관할·연락처·최종확인일 | 100% — 미충족 시 미노출          |
| 좌표           | 100% (주소 없음, 좌표가 유일 식별자)  |
| 최종 확인일 1년 이내 | 90%↑                      |


**참고 지표 (계측 미도입)**

- 노지 상세 열람 중 관할 연락처 노출·클릭 비율

### 2.3 명시적 비목표

## 3. 범위와 단계

### 3.1 MVP 판정 기준

둘을 모두 충족해야 MVP 달성이다.

1. **데이터 마일스톤(§2.2 H1) 충족** — 행동 지표는 제외
2. **웹·iOS 양 플랫폼 배포 완료** (§3.4)

**MVP 우선순위**

1. 탐색 플랫폼 구현 — 웹 + iOS
2. 데이터 수집·정제 후 서비스 반영

### 3.2 단계 로드맵


| 단계  | 내용                                          | 가설  |
| --- | ------------------------------------------- | --- |
| 1   | 웹·iOS 탐색 플랫폼 구현 + 공공 데이터 수집·정제 → **MVP 판정** | H1  |
| 2   | 사용자 행동 계측 도입(필수) / 노지 적재 기획·착수              | —   |
| 3   | 노지 노출 (§4.4 요건 충족분)                         | H2  |


**1단계 완료 조건**

- 지도 SDK가 통합되어 지도 모드가 실제 좌표로 동작할 것 — 목록 모드만으로는 미완료
- `apps/mobile` 구축 후 §5 전 기능이 iOS에서 동작하고 App Store에 배포될 것

### 3.3 약속의 크기와 대외 문구 규칙

노지 합법성에 대한 서비스의 약속은 단계별로 다르다.


| 시점  | 약속                              |
| --- | ------------------------------- |
| MVP | 관할·연락처·최종확인일을 모아 **문의 비용을 줄인다** |
| 지향점 | 신뢰 가능한 수준의 필터링으로 합법 여부 제공       |


상향 조건: 데이터 실현성 스파이크 실행 결과(§7).

**MVP에서 쓰지 않는 표현**

- "합법 야영지만 모았다" 류의 판정 뉘앙스
- 노지·백패킹 스팟을 전면에 내세우는 홍보 — 3단계까지 노출되지 않음

### 3.4 플랫폼

**MVP 달성 조건은 웹과 iOS 앱이 동일한 수준으로 배포되는 것이다.**
웹 선행 출시로 MVP를 대체하지 않는다.


| 항목      | 결정                                        |
| ------- | ----------------------------------------- |
| 대상      | 웹 + iOS 네이티브 앱 (React Native)             |
| Android | **MVP 제외.** RN이라 대체로 따라오지만 MVP 조건에 넣지 않는다 |
| 코드 공유   | `packages/` 공유 로직을 `apps/mobile`에서 재사용    |
| 기능 동등성  | §5 전 기능이 양 플랫폼에서 동일 수준으로 동작               |
| PWA     | 폐기                                        |
| 오프라인 열람 | MVP 제외. 온디바이스 캐싱은 이후 재검토                  |


§5.4 지도 SDK(D14)가 이 전제 위에 있다 — 웹만 고려하면 다른 결론이 나온다.

## 4. 데이터 정의

### 4.1 대상 범위와 경계


| 구분  | 내용                                           |
| --- | -------------------------------------------- |
| 포함  | 자연휴양림, 국립공원 야영장, 국민여가캠핑장, 지자체 야영장, 노지 백패킹 스팟 |
| 제외  | 민간 오토캠핑장·글램핑장                                |


**소스 확장 규칙** — 소스가 늘어도 공개 데이터 계약은 바꾸지 않는다.
소스별 필드 차이는 수집 단계에서 흡수하고, 계약에 없는 항목은 버리거나 기존 속성에 매핑한다.

### 4.2 category 어휘


| 코드                          | 라벨       | 상태  |
| --------------------------- | -------- | --- |
| `RECREATIONAL_FOREST`       | 자연휴양림    | 기존  |
| `NATIONAL_PARK_CAMPGROUND`  | 국립공원 야영장 | 신규  |
| `PUBLIC_LEISURE_CAMPGROUND` | 국민여가캠핑장  | 신규  |
| `MUNICIPAL_CAMPGROUND`      | 지자체 야영장  | 신규  |
| `BACKPACKING`               | 백패킹(노지)  | 기존  |


- 필터 UI 상위 그룹: **공공 야영시설 / 노지**
- 차박·비박은 category가 아니라 **접근 방식 속성**(도보 / 차량 진입)
- `BACKPACKING`만 활동명이라 결이 다르나 유지 — 변경 비용이 이득보다 크다

### 4.3 신뢰도·상태 모델

**노출 게이트** — 검수를 통과해 공개 상태가 된 스팟만 노출한다.

**신뢰도 등급**


| 등급  | 기준                           | 표시       |
| --- | ---------------------------- | -------- |
| 1   | 공식 소스 + 핵심 속성 완비             | —        |
| 2   | 신뢰 소스지만 일부 누락, 또는 커뮤니티 교차 확인 | —        |
| 3   | 단일 비공식 소스, 미검증               | "미검증" 뱃지 |


3등급의 안전 관련 속성(화기 등)은 "확인되지 않음"으로 일괄 표시한다.

**핵심 속성 4종** — 화기 · 편의시설 · 예약 방식 · 접근성.
1등급 판정 기준이자 §2.2 마일스톤의 대상이다.


| 속성 | 상세 |
|---|---|
| 화기 | 불피움/화로대/장작 가능 여부, 허용 범위 |
| 접근성 | 차박 가능, 진입로 상태(비포장/4WD), 주차, 도보/대중교통 |
| 편의시설 | 화장실, 개수대, 식수원, 전기, 샤워실, 매점 거리 |
| 예약/요금 | 예약 방법, 외부 예약 링크, 요금, 선착순 여부 |


### 4.4 노지 등재 요건

아래를 모두 충족해야 노출한다. 미충족 시 미노출.

- 관할 기관
- 연락처
- 최종 확인일
- 좌표 (주소가 없으므로 유일 식별자)

검수자가 등재 시 확인한다. 합법 여부 **판정이 아니라 확인 결과의 기록**이다.

## 5. 기능 명세

각 기능은 **목적 → 동작 → 확정 계약 → 수용 기준** 4블록으로 기술한다.
구현 현황은 STATUS.md §7.

**플랫폼** — 목적·동작·확정 계약·수용 기준은 웹과 iOS에 동일하게 적용된다. 구현 현황은 STATUS.md §7.

### 5.1 홈

**목적** — 진입점. 검색으로 유도하고 큐레이션된 스팟을 노출한다.

**동작**

- 검색 바 → 검색 화면 이동
- 큐레이션 캐러셀 2종(추천 / 인기) — 카드 탭 시 상세로 이동

**확정 계약**


| 항목     | 값                |
| ------ | ---------------- |
| 캐러셀 소스 | 고정 그룹 식별자 2개로 조회 |
| 조회 건수  | 그룹당 10           |
| 렌더     | 서버 프리페치 후 하이드레이션 |


**수용 기준**

- 캐러셀 카드에서 상세로 이동한다
- 그룹 조회 실패 시 홈 전체가 깨지지 않는다

### 5.2 검색·목록

**목적** — 조건에 맞는 스팟을 찾고 비교한다.

**동작**

- 검색어 입력 → 결과 목록. 검색어 없으면 안내 화면
- 스크롤 하단 도달 시 다음 페이지 자동 로드
- 결과 수 표시. 첫 조회 완료 전에는 `—`, 상한 초과 시 `+` 접미

**확정 계약**


| 항목      | 값                                  |
| ------- | ---------------------------------- |
| 조회      | 검색어·카테고리·지역·bbox·커서·페이지 크기         |
| 페이지 크기  | 최대 50                              |
| 페이지네이션  | 커서 방식. 다음 커서와 추가 여부를 응답에 포함        |
| 목록 항목   | 이름 · 신뢰도 등급 · 썸네일 · 지역 · 카테고리 · 좌표 |
| 필터 전환 중 | 직전 결과 유지 (0건 오독 방지)                |


**수용 기준**

- 필터를 바꿔도 결과 수가 순간적으로 0으로 표시되지 않는다
- 첫 조회 전 결과 수는 0이 아니라 미확정으로 표시된다

### 5.3 필터

**목적** — 카테고리·지역으로 결과를 좁힌다.

**동작**

- 데스크톱은 좌측 레일, 모바일은 바텀시트
- 칩 토글. 다중 카테고리 선택 가능
- 초기화 시 카테고리·지역만 제거하고 검색어는 유지

**확정 계약**


| 항목        | 값                           |
| --------- | --------------------------- |
| 상태 저장소    | **URL 쿼리 파라미터가 단일 진실**      |
| 갱신 방식     | 히스토리 교체(replace), 스크롤 위치 유지 |
| 카테고리      | 쉼표 구분 다중 선택                 |
| 지역 ↔ bbox | **상호 배타.** 한쪽 설정 시 다른 쪽 제거  |
| 카테고리 옵션   | §4.2의 **공공 4종** (노지는 3단계)   |
| 지역 옵션     | 실데이터 기반 확정                  |


**수용 기준**

- 필터 상태가 URL에 반영되어 새로고침·뒤로가기에서 복원된다
- 연속으로 칩을 눌러도 앞선 선택이 사라지지 않는다

### 5.4 지도 탐색

**목적** — 위치 기준으로 스팟을 찾는다. 노지는 주소가 없어 좌표가 유일 식별자다.

**동작**

- 목록 / 지도 2모드 토글. **기본 진입은 목록**
- 지도 이동 시 자동 재검색 없음. "이 지역 재검색" 버튼을 눌렀을 때만 조회
- 모바일은 지도 위 결과 바텀시트, 데스크톱은 좌우 분할

**확정 계약**


| 항목       | 값                                      |
| -------- | -------------------------------------- |
| SDK      | **네이버 지도** (웹 JS API / 앱 네이티브 SDK)     |
| bbox 형식  | `최소경도,최소위도,최대경도,최대위도` — **경도 우선**      |
| 지도 조회    | 목록과 별도. 좌표·신뢰도만 담은 경량 응답               |
| 지도 응답 좌표 | 항상 존재 (좌표 없는 스팟 제외)                    |
| 카메라 상태   | 이동 종료 후 디바운스하여 URL 반영                  |
| 커서 무효화   | bbox 변경 시 이전 커서 거부 → 처음부터 재조회          |
| 데스크톱 분할  | 45:55 (960~~1199px) · 35:65 (1200px~~) |
| 모바일 시트   | 4단 스냅 — 핸들 / 25% / 55% / 90%. 초기 40%   |


**수용 기준**

- 지도 모드에서 실제 좌표로 핀이 렌더된다
- 지도를 움직여도 자동 재조회가 발생하지 않는다
- 모드 전환·시트 스냅 변경 시 지도가 회색으로 남지 않는다

### 5.5 스팟 상세

**목적** — 한 스팟의 정보를 확인하고 예약·문의로 이어진다.

**동작**

- 서버에서 조회해 렌더. 비공개·삭제 스팟은 404 페이지
- 구성: 히어로 이미지 → 헤더(이름·신뢰도·카테고리·테마) → 위치 → 설명 → 시설·제원 → 액션 바
- 신뢰도 3등급은 "미검증" 뱃지, 안전 관련 속성은 "확인되지 않음"

**확정 계약**


| 항목     | 값                                                                                                                |
| ------ | ---------------------------------------------------------------------------------------------------------------- |
| 조회     | 스팟 식별자 단건                                                                                                        |
| 비공개·삭제 | 404 — 오류가 아닌 정상 분기                                                                                               |
| 표시 항목  | 이름 · 주소 · 좌표 · 연락처 · 예약 링크 · 카테고리 · 테마 · 편의시설 · 화기 유형 · 구획 수 · 면적 · 반려동물 · 유료 여부 · 설명 · 출처(공식 / 커뮤니티 제보 / 현장 확인) |
| 빈 필드   | 항목 자체를 숨긴다                                                                                                       |


**수용 기준**

- 빈 필드가 "없음"이 아니라 미표시로 처리된다
- 존재하지 않는 스팟에서 오류 화면이 아닌 404가 뜬다

### 5.6 계정·인증

**목적** — 로그인 상태를 유지한다.

**동작**

- Google 계정으로 로그인 (전체 리다이렉트)
- 세션은 암호화 쿠키. 만료 시 재발급·회전
- 재발급 실패 시 로그아웃 처리

**확정 계약**


| 항목       | 값                                     |
| -------- | ------------------------------------- |
| 인증 수단    | Google. **카카오는 MVP 직후 순차 도입** (배제 아님) |
| 토큰 발급 주체 | 백엔드                                   |
| 재발급 토큰   | 클라이언트에 노출하지 않는다                       |


**경계** — **MVP 탐색 기능은 전부 비로그인으로 동작한다.**
검색·목록·필터·지도·상세 어디에도 로그인 요구가 없다. 로그인이 여는 기능은 MVP 범위 밖이다.

**수용 기준**

- 비로그인 상태에서 모든 탐색 기능이 동작한다
- 세션 만료 시 "로그인됨"인데 요청이 실패하는 상태에 갇히지 않는다

### 5.7 공통 상태 (로딩·빈·에러)

**목적** — 로딩·빈 결과·오류를 일관되게 처리한다.

**동작**


| 상태      | 처리          |
| ------- | ----------- |
| 최초 로딩   | 스켈레톤 카드     |
| 추가 로딩   | 목록 하단 로딩 표시 |
| 빈 결과    | 조건 변경을 안내   |
| 오류      | 원인 안내 + 재시도 |
| 필터 전환 중 | 직전 결과 유지    |


**확정 계약**


| 항목        | 값               |
| --------- | --------------- |
| 빈 결과 ≠ 오류 | 별개 화면으로 구분한다    |
| 결과 수 미확정  | 0이 아닌 `—`로 표시   |
| 커서 무효화    | 오류 화면 없이 자동 재조회 |


**수용 기준**

- 로딩 → 결과 전환에서 레이아웃이 밀리지 않는다
- 오류 화면에서 재시도가 가능하다
