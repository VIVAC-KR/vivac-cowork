# 🌲 VIVAC — 백패킹 캠퍼를 위한 신뢰 가능한 장소 인덱스

> **"여러 곳을 안 뒤져도, 합법적으로 잘 수 있는 백패킹 장소를 한 번에 찾아주는 앱."**

캠핑장, 노지, 차박지, 비박지, 자연휴양림 등 흩어진 야영 가능 장소 정보를 한데 모아 지도로 탐색하고, 장소마다 야영·취사·화기의 합법성 정도와 신뢰도를 확인할 수 있는 서비스입니다.

> 2026-08-04, `기획서_문제정의_수정안.md`와 `PRODUCT_TEMP.md`의 상충 내용을 사용자 확인을 거쳐 이 문서로 통합했습니다. `PRODUCT_TEMP.md`는 이 문서로 병합 완료되어 더 이상 별도 갱신하지 않습니다. 병합에 쓰인 원본 문서들은 [docs/archive/planning-source/](archive/planning-source/)에 보관돼 있습니다(2026-08-04, 프로젝트 루트에 흩어져 있던 `docs_to_be_merge/`·시장조사 자료를 통합).

## 문제

- 야영지의 합법성·최신성·적합성을 한 곳에서 확인할 수 있는 신뢰 인덱스가 없어, 백패킹 여정 때마다 여러 채널(SNS·유튜브·네이버 카페·지도 앱)을 교차 탐색하며 높은 정보 비용을 치릅니다.
- 야영·취사·화기의 법적 허용 여부는 공식 채널에서도 찾기 어렵고, 도립·군립공원·해수욕장 조례·보호구역 전환 등 규제가 복잡하고 자주 바뀌어 "작년엔 됐는데 지금은 금지"를 알 수 없습니다. 숙련자도 노지 야영 허가 여부를 매번 관할 기관에 직접 확인합니다.
- 기존 서비스(캠핏, 캠핑톡, 고캠핑)는 예약형 캠핑장 중심이라 노지·차박·비박은 다루지 않고, 노지 특화 서비스(오지캠핑지도·야영)는 신뢰도·합법성 검증 체계가 없습니다.
- 책임감 있는 사용자일수록 보존을 위해 정확한 위치 공유를 자제해, 신뢰할 정보가 구조적으로 희소해지는 역선택 구조가 있습니다.

## 타겟

**25~39세, 월 1회 이상 활동하는 백패킹 지향 액티브 캠퍼** — 백패킹을 즐기거나, 캠핑에서 백패킹으로 전환·확장 중인 사용자입니다.

- 반복적인 장소 탐색 문제를 경험하고, 스팟 후기·사진 등 정보를 직접 생산할 가능성이 높습니다.
- 합법성 불확실성은 입문자만이 아니라 숙련자도 겪는 페인입니다 — 노지 허가는 시시각각 변동해 숙련자도 매번 관할 기관에 확인합니다.
- JTBD: "나는 새로운 백패킹 장소를 찾을 때, 여러 사이트를 돌아다니지 않고 내 취향과 조건에 맞는 검증된 장소를 빠르게 발견하고 싶다."

> [검증 필요] 위 타겟 정의·JTBD는 2차 리서치와 내부 가정에 기반합니다. 1차 사용자 검증(인터뷰·설문)이 필요합니다.

## 차별화

1. **노지/차박/비박 커버리지** — 기존 강자는 예약형 수익 모델 때문에 의도적으로 커버하지 않는 영역입니다. 분산된 공공 API와 노지 규정을 수집·정규화한 통합 스키마는 초기 구축 비용이 높아 후발 진입 장벽이 됩니다.
2. **합법성 '정도' 표기 + 신뢰도 등급** — 합법 여부를 단정·보장하는 대신 관계법령 기반의 합법성 정도를 단계적으로 제시하고, 모든 정보에 `trust_tier`(신뢰도 등급)와 출처를 명시합니다. "확인된 것만 보여주기" 대신 "모두 보여주되 신뢰도를 밝히기"로 커버리지를 극대화합니다.
3. **캠퍼 관점 필터** — 화기, 접근성, 편의시설, 예약/요금 등 실사용 기준.

> 단순 통합 자체는 유사 서비스(오지캠핑지도·야영)가 이미 시도하고 있어 차별점이 아닙니다. 전환을 만드는 것은 통합이 아니라 **합법성 검증·신뢰**이며, 그 실현 가능성이 검증되지 않으면 차별점이 소멸합니다 → 아래 "미해결 이슈" 참고.

## 플랫폼

**웹 MVP 우선 → 빠르게 React Native 네이티브 앱으로 확장**합니다.

- PWA는 폐기합니다. 오프라인/캐싱을 목표로 한 PWA 특화 구현 대신, 빠른 검증을 위한 일반 웹 MVP로 시작합니다.
- 웹 MVP 출시 후 2주 내 RN(React Native) 기반 네이티브 앱 완성을 목표로 합니다. `packages/` 공유 로직을 `apps/mobile`에서 재사용합니다.
- 오프라인 열람은 MVP 범위에서 제외하고, RN 네이티브 앱 단계에서 온디바이스 캐싱으로 재검토합니다.

## MVP 구현 우선순위

1. **분산된 공공 야영장 데이터 통합** — 고캠핑(한국관광공사)·산림청·국립공원 API 3종을 통합 스키마로 수집·정제합니다.
2. **노지 야영 스팟 데이터를 지도상에 표시** — 공공 API로 커버되지 않는 노지·비박지를 운영팀 검수를 거쳐 추가하고, 지도·목록으로 탐색할 수 있게 합니다.
3. **야영 합법 여부 검증 로직 적용** — 확보된 스팟에 합법성 필터링 로직과 지도상 법령 레이어를 적용합니다. 착수 전 아래 "데이터 실현성 검증" 항목을 먼저 확인합니다.
4. **UGC 인프라 구축** — 제보("정보가 틀렸어요" / "새 스팟 제보"), 리뷰 등 사용자 기여 체계입니다. 후순위입니다.

### 기능 범위

- **지도 기반 탐색**: 주변/지역별 탐색, 유형 필터(캠핑장/노지/차박/비박/휴양림) + 4대 속성 필터
- **스팟 상세**: 4대 속성 + `trust_tier` 뱃지 + 출처 표시(공식/커뮤니티 제보/현장 확인) + 합법성 정도(법령 레이어)
- **온보딩 소셜 로그인**: Google 우선 적용, 카카오는 배제가 아니라 순차 도입(MVP 직후)
- **홍보 랜딩페이지 + GA 연동**: CBT 유저 모집, 수요·핵심 이벤트 측정

| 속성 | 상세 |
|---|---|
| 화기 | 불피움/화로대/장작 가능 여부, 허용 범위 |
| 접근성 | 차박 가능, 진입로 상태(비포장/4WD), 주차, 도보/대중교통 |
| 편의시설 | 화장실, 개수대, 식수원, 전기, 샤워실, 매점 거리 |
| 예약/요금 | 예약 방법, 외부 예약 링크, 요금, 선착순 여부 |

### MVP 제외

- PWA, 오프라인 캐싱(위 "플랫폼" 참고)
- 폐쇄형 커뮤니티, 크라우드소싱 등록, 매너 평판, GPX/등고선 필드 도구, 장비 어시스턴트 — 중장기 로드맵으로 이연

## 데이터 전략

- 1차 공급 소스를 이원화합니다 — ① 공공 API 3종으로 콜드 스타트를 회피하고, ② 커뮤니티·웹에서 검증된 노지 야영지 데이터를 운영팀이 검수해 반영합니다.
- 출시 범위를 의도적으로 좁힙니다 — 국가 기관·지자체가 관할하는 검증된 야영지(자연휴양림, 국민여가캠핑장 등)부터 우선 공개하고, 노지는 완결성이 확보된 곳부터 점진 확장합니다.
- 신뢰 확보 방식: 검증 우선 공개, 합법성 '정도' 안내(단정·보장 아님), 출처·최종 확인일 표기, 불확실 정보는 "확인 필요"로 정직하게 표시, 정기 갱신 + 제보 채널 운영.
- 데이터 row별 `pipeline_status`(RAW→PUBLISHED 처리 단계)와 `trust_tier`(신뢰도 1~3등급) 필드 정의는 [data-pipeline.md](data-pipeline.md)를 참고하세요. 두 필드 모두 vivacapi-core에 구현되어 있습니다.

## 수익 모델

MVP는 수익화 없이 성장을 우선합니다. 향후 후보:

- **B2C 프리미엄 구독('Backpackers Pro')** — 핵심 탐색·합법성 정보는 무료, 고급 필터·오프라인 지도·GPX/코스·독점 데이터 등 심화 가치를 유료화
- **B2B 데이터 라이선싱** — 검증된 야영지·합법성 데이터셋을 공공기관·아웃도어 브랜드·여행 사업자에 제공
- **브랜드 제휴** — 장비 브랜드·큐레이션 거점과의 가치 부합형 제휴(비침투적 광고 지양)
- **C2C 중고장터**(중장기) — 고관여·고지출 장비 소비 특성 기반 거래 중개

## 미해결 이슈

- **데이터 실현성 검증 미실행** — "공공 API + 지자체 자료로 장소 단위 합법성을 어느 범위·정확도·갱신 시차로 산출할 수 있는가"가 아직 검증되지 않았습니다. MVP 3순위(합법성 검증 로직) 착수 전 확인을 권장합니다. 상세 설계는 [docs/archive/planning-source/VIVAC_데이터실현성_스파이크_검증설계.md](archive/planning-source/VIVAC_데이터실현성_스파이크_검증설계.md)를 참고하세요(archive 폴더에 있지만 미실행 상태로 유효합니다).
