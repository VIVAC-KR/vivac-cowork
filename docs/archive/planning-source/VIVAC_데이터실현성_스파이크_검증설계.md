# VIVAC 데이터 실현성 스파이크 — 검증 설계

> 작성 목적: VIVAC의 단일 최대 리스크 — "공공 데이터로 장소 단위 합법성을 산출·유지할 수 있는가" — 를 MVP 본 개발 착수 **전에** 검증한다.

## 왜 최우선인가

VIVAC을 데이터/콘텐츠 프로덕트로 정의한 이상, **데이터 자산이 곧 제품**이다. 합법성 검증 정보는 MVP의 유일한 차별점(기획서 232번)이자 동시에 유일하게 기술적으로 미검증인 가정(236번)이다. 이게 깨지면 MVP는 "또 하나의 통합 앱"으로 붕괴하므로 — 문서 스스로 그건 차별점이 아니라고 했다 — UI·로그인·랜딩페이지보다 **먼저** 검증한다.

## 검증 질문 (한 문장)

"공공 API 3종 + 지자체 자료로 장소 단위 합법성을 **어느 범위(커버리지)**까지, **어느 정확도**로 산출할 수 있으며, 규제 변동을 **어느 시차(갱신 latency)**로 반영할 수 있는가?"

## 검증할 리스크 가정 (우선순위 순)

1. **커버리지** — 각 소스의 필드만으로 야영·취사·화기 합법성을 장소 단위로 도출할 수 있는가. 장소 유형별로 가능/불가를 구분한다.
2. **갱신 latency** — "시시각각 변하는" 노지 허가 변동을 포착할 경로가 존재하는가, 시차는 얼마인가. (숙련자 인터뷰에서 드러난 핵심 — 효용이 검증된 만큼 갱신이 곧 사활)
3. **정확도** — 도출한 "합법성 정도" 단계가 실제 법령·관할 답변과 일치하는가.

핵심 축은 두 개다: **커버리지 × 갱신 latency.** 둘 다 통과해야 가치가 전달된다. 정확도는 그 위의 품질 게이트.

## 방법 (장소 유형 층화)

표본을 유형별로 층화한다: 자연휴양림 / 국민여가캠핑장 / 국립공원 / 노지·비박지.

1. **소스 필드 인벤토리** — GoCamping·산림청·국립공원 API 응답 스키마를 수집하고, 합법성 산출에 쓸 수 있는 필드를 매핑한다. (어떤 필드도 "야영 합법" 여부를 직접 주지 않을 가능성이 높음 → 파생 규칙의 필요성·설계 가능성을 함께 확인)
2. **정답셋 구축** — 유형별 표본 장소 N개(권장 유형당 10, 총 ~40)에 대해 운영팀이 관계법령 + 관할 확인으로 "정답 합법성"을 수기 구축한다.
3. **대조** — API/파생규칙 도출값을 정답셋과 대조해 커버리지율·정확도를 측정한다.
4. **갱신 시차 측정** — 최근 규제 변동 사례 K건(예: 해수욕장 조례 개정, 보호구역 전환)을 추적해 변동이 원천(공고·API)에 반영되는 시차를 측정한다. 노지 변동의 포착 가능 경로(지자체 공고·조례 개정 등)를 함께 탐색한다.

## 측정 지표 & 의사결정 게이트

측정:
- 커버리지율 = 산출 가능 장소 / 표본 (유형별)
- 정확도 = 정답 대비 일치율
- 갱신 시차 = 변동~반영 중앙값·최악값
- 폴백률 = "확인 필요"로 떨어지는 비율

게이트 (임계값 X·Y·Z는 팀 합의 — 아래는 구조 예시):
- 검증 야영지(휴양림·국민여가·국립공원) 커버리지 ≥ X% & 정확도 ≥ Y% → **합법성을 차별점으로 유지**, 해당 유형부터 우선 출시(기획서 264번의 "검증 우선 공개"와 정합).
- 노지 폴백률 > Z% → 노지는 "정답 제공"을 포기하고 **"확인 필요 + 관할 연락처·최종확인일 집약"**으로 범위를 축소, 차별점 메시지를 재정의.

## 가치 역설 경고 (숙련자 인터뷰 연계)

가장 가치 높은 질의(변동성 큰 노지 허가)가 동시에 가장 산출·갱신이 어렵고 "확인 필요" 폴백 확률이 높다. 폴백률이 높으면 사용자는 결국 관할 기관에 전화 — **지금 하는 워크어라운드로 회귀**한다. 따라서 노지에 대해서는 "정답을 준다"가 아니라 **"관할·연락처·최종확인일을 한 곳에 모아 문의 비용 자체를 줄인다"**는 축소된 가치로 재정의하는 시나리오를 게이트에 미리 포함해 둔다. 이 경우에도 효용은 남는다(숙련자도 매번 문의하므로) — 다만 약속의 크기가 달라지므로 가치 제안 문구를 그에 맞춰 잠가야 한다.

## 산출물 / 리소스

- 기간: 1~2주 스파이크. **BE 엔지니어 협의 필수**(API 접근 권한·스키마 확인).
- 산출물: 유형별 커버리지·정확도·갱신 시차 리포트 + 출시 범위 권고안 + 차별점/가치 제안 메시지 확정안.
- 후속: 게이트 결과를 기획서 5·6번 절(가치 제안·MVP 범위)에 역전파해 다시 잠근다.
